# Plan 07-01: Subscription Data Models & Plan Limits Enforcement

## Goal
Implement the core subscription data architecture in `backend/subscriptions/`:
- `Plan` model (name, interval, price_paise, limits JSON, is_active).
- `Subscription` model (shop, plan, status [TRIAL, ACTIVE, GRACE, EXPIRED], trial_end, current_period_end, grace_end).
- `SubscriptionEvent` model (webhook event ID, provider, raw_payload, processed, created_at).
- Middleware / DRF permission enforcing read-only status when subscription has expired past the 5-day grace period (`SUBS-07`, `SUBS-08`, `SUBS-09`).
- Auto-assign 14-day trial upon shop creation (`SUBS-01`).

## Requirements Covered
- **SUBS-01**: 14-day free trial on signup.
- **SUBS-02**: Configurable Plan model in DB.
- **SUBS-03**: Plan limits (employees, shops, backup days).
- **SUBS-07**: Server-side subscription status enforcement.
- **SUBS-08**: 5-day grace period followed by read-only mode.
- **SUBS-09**: Data retention & export access.

## Tasks
1. Create `backend/subscriptions/` Django app and register in `INSTALLED_APPS`.
2. Define models: `Plan`, `Subscription`, `SubscriptionEvent`.
3. Create `SubscriptionService` for trial initiation, status checks, and limit validations.
4. Implement `SubscriptionAccessMiddleware` or DRF permission class blocking unsafe HTTP methods (POST, PUT, PATCH, DELETE) when in read-only mode.
5. Create default plans seed fixture/migration (Monthly, Quarterly, Yearly).

## Verification
- Unit test ensuring 14-day trial auto-starts.
- Unit test ensuring write requests fail with 403 when subscription is expired > 5 days.
- Unit test ensuring GET requests succeed even when expired.
