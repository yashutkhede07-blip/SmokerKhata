# Plan 05-03: Monotonic Pull API & Comprehensive Sync Verification Suite

## Goal
Implement `GET /api/sync/pull` for monotonic cursor-based delta syncing, and build the comprehensive test suite validating all 10 sync requirements:
- Monotonic cursor querying on `SyncJournalEntry` (never missing updates or repeating processed sequences).
- Pagination support with `has_more` and `next_cursor`.
- Test suite validating idempotency, batch replay, offline sequence reconciliation, cursor increments, and conflict resolution rules.

## Requirements Covered
- **SYNC-05**: Monotonic sequence cursor pull (never timestamp-based).
- **SYNC-07**: Server payload providing sync status info for client header display.
- **SYNC-10**: End-to-end sync tests: replay/idempotency, offline-to-online reconnection, conflicting edits, and simulated retry resilience.

## Tasks
1. Implement `SyncPullView` at `/api/sync/pull/`:
   - Query parameters: `cursor` (integer sequence, defaults to 0), `limit` (max records, default 100).
   - Filter `SyncJournalEntry.objects.filter(shop=request.shop, sequence__gt=cursor).order_by('sequence')[:limit]`.
   - Calculate `next_cursor` and boolean `has_more`.
   - Return `{ "changes": [...], "next_cursor": ..., "has_more": ... }`.
2. Connect Django signals or service hooks across `Item`, `Category`, `Customer`, `Supplier`, `Bill`, `CustomerLedgerEntry`, and `SupplierLedgerEntry` so server-originated changes (e.g. from web admin or API) also write to `SyncJournalEntry`.
3. Create `backend/tests/test_sync.py`:
   - `test_sync_push_idempotent_replay`: Replay batch twice; assert no duplicate records.
   - `test_sync_pull_monotonic_cursor`: Push changes, pull cursor 0, pull next cursor; assert only deltas returned.
   - `test_offline_bills_reconciliation`: Two devices pushing offline bills with distinct device IDs without clash.
   - `test_sync_conflict_resolution`: Append-only ledgers preserved; mutable entity updates handled cleanly.
4. Execute full pytest suite and verify suite runs in under 30 seconds.
