# Plan 05-02: Batch Push API & Transactional Idempotent Processing

## Goal
Implement `POST /api/sync/push` endpoint to process batches of offline operations sent from client devices:
- Wrap the entire operation batch in an atomic database transaction.
- Dispatch each operation to entity domain handlers (bills via `BillingService`, ledgers, items, customers, suppliers).
- Prevent duplicate execution using `SyncOperation` lookup by `(shop, idempotency_key)`.
- Enforce append-only rules for financial & stock entries (`SYNC-08`) and last-write-wins for mutable non-financial entities (`SYNC-09`).
- Record journal mutations and return confirmed idempotency keys with the latest server cursor.

## Requirements Covered
- **SYNC-03**: Backend push receiver handling retries from client outbox.
- **SYNC-04**: Batch processing in one DB transaction, deduplicating via idempotency keys.
- **SYNC-06**: Explicit acknowledgement of processed idempotency keys so client can safely purge outbox.
- **SYNC-08**: Append-only preservation of financial and stock records.
- **SYNC-09**: Conflict handling for non-financial entities.

## Tasks
1. Create `SyncPushSerializer` validating the incoming batch payload (`device_id`, list of operations with `idempotency_key`, `entity_type`, `action`, `entity_id`, `payload`, `timestamp`).
2. Implement `SyncEngineService.process_batch(shop, device_id, operations)`:
   - Check existing `SyncOperation` keys; skip already-processed keys immediately.
   - For new operations, dispatch by `entity_type`:
     - `bill`: Invoke `BillingService.create_bill_atomic` ensuring exact offline `bill_number` and sequences are honored.
     - `customer_ledger`: Append credit or payment transaction without overwriting.
     - `supplier_ledger`: Append bill or payment transaction.
     - `item` / `customer` / `supplier`: Upsert with Last-Write-Wins logic, recording changes to journal.
   - Record `SyncOperation` rows as processed.
   - Return list of processed/acknowledged idempotency keys and latest cursor.
3. Expose `SyncPushView` at `/api/sync/push/` requiring shop authentication.

## Verification
- Test replay of identical batch produces HTTP 200 with all keys acknowledged, but zero duplicate rows created.
- Test invalid operation fails safely without corrupting batch.
