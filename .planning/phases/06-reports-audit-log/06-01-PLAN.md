# Plan 06-01: Immutable Audit Trail & Change Logging

## Goal
Implement a centralized, immutable audit logging subsystem (`backend/audit/`):
- Record all lifecycle mutations (`CREATE`, `UPDATE`, `SOFT_DELETE`) across core entities (`Item`, `Category`, `Customer`, `Supplier`, `Bill`, `CashBookDay`).
- Capture acting user, UTC timestamp, `old_values`, `new_values`, and conflict resolution notes (`AUDT-01`, `AUDT-04`).
- Guarantee strict append-only immutability at the database model level (`AUDT-03`).
- Provide owner/manager query endpoints to inspect audit records.

## Requirements Covered
- **AUDT-01**: User, timestamp, old/new value capture on business model mutations.
- **AUDT-02**: Soft-delete confirmation and audit trail.
- **AUDT-03**: Audit log immutability (no update/delete).
- **AUDT-04**: Preserving conflict resolution losing versions in the audit log.

## Tasks
1. Create `backend/audit/` Django app and register in `INSTALLED_APPS`.
2. Define model `AuditLogEntry(id, shop, user, model_name, record_id, action, old_values, new_values, notes, created_at)`.
   - Prevent modifications or deletions in `save()` and `delete()`.
3. Create `AuditService.record_audit(...)` helper.
4. Hook Django `post_save` and `post_delete` / soft-delete signals for `Item` and related entities to record audits automatically.
5. Expose `GET /api/audit/logs/` protected by `IsShopManagerOrOwner`.

## Verification
- Unit test verifying audit creation when an item price changes.
- Unit test ensuring `AuditLogEntry` raises ValueError on update or delete.
